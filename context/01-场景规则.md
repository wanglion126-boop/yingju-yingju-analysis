# 场景规则

版本：`1.0.0`。这是完整的初始草稿，适用于用户提供的离线抽象对抗场景。只使用中性对象与代号，不追查来源或身份。

## A. 场景对象

| 代号或类别 | 含义 |
| --- | --- |
| A0 | 主要分析主体 |
| A1、A2 等 | 同侧单位 |
| B1、B2 等 | 对侧单位 |
| A-J、B-J | 角色引用，不等于具体身份；角色与实际单位的关系未配置时保持未知 |
| A0-C | 主体可部署的协同单位；列出对象不代表已部署或在场 |
| L1、L2、L3 | 不同通道 |
| 固定防守节点 | 位置固定的防守对象，是否存在、所属侧与状态由任务给出 |
| 周期资源单位 | 按任务机制出现的资源对象，周期和收益未提供就保持未知 |
| 周期推进单位 | 周期性参与推进的对象，出现时间、位置与状态须独立记录 |
| 增益与数值状态 | 耐久、能力可用性、增益等状态，不补充具体数值或效果 |

角色、类型、具体实例必须分开：`entityKind` 标识 `role`、`type` 或 `instance`，`typeRef` 只连接到类型。角色不能作为某个具体身份的默认别名。同一种资源在不同位置或不同所属侧是不同实例；实例 ID 不可复用。示例对象表中的类型不表示实例已经出现，未知所属侧使用 `unknown`。

## B. 主体抽象能力

以下是**本工作区的初始抽象模型，可由任务配置覆盖**，不是对任何实际机制的断言：

- 主体具有一定距离的持续输出能力。
- 主体可部署协同单位，在不同位置产生影响；主体与协同单位可以承担不同任务。
- K1 为区域作用能力，具体效果待配置。
- K2 具有位置调整作用，具体效果待配置。
- K3 可部署协同单位并产生控制，具体效果待配置。
- 不预设具体数值、距离、冷却和持续时间。
- 不预设主体与协同单位之间的耐久、回收和消失关系。

`entities.json` 的能力必须通过 `ownerRef` 关联所属对象。任务显式配置优先于此模型；若配置与事件冲突，列出冲突等待确认，不能静默改写材料。一次使用 K3 不足以推出部署数量、控制是否命中、控制时长或随后是否可再次使用。

## C. 任务与条件

分析需要结合资源获取、固定节点推进、同侧协作、当前与下一处行动的衔接，以及对侧防守、主动进攻或其他位置交换。候选行动的收益方向依赖当时条件，不能写成下列无条件结论：

- 多单位交战必然有利。
- 对侧不在就必然可以进攻。
- 对侧改变路线就必然亏损。
- 使用控制后就可以深入。
- 缺少某能力就完全不能推进。
- 未取得资源等于永久损失。

资源是否安全、是否仍可取得、推进是否需要特定单位、同侧是否能参与，均须有本任务依据；没有提供就使用条件分支。

## D. 信息与时间

- 最后观察位置不等于当前确定位置。旧观察不能直接填入当前状态。
- 时间支持精确秒数、闭合时间区间和未知。任务必须约定时间起点；不推造未知端点。
- `occurredAt` 是事件发生时间，`knownAt` 是该信息对分析主体可用的时间。记录者事后知道，不代表主体当时知道。
- 在节点 t 的判断只使用 `knownAt` 可确定不晚于 t 的信息。区间跨越 t 或获知时间未知时，列为不确定，不能作为当时已知事实。
- 判断到达速度、先后到场或转移是否来得及，必须有路径、距离、速度或实际时序依据。`sequenceIndex` 只是记录顺序，不补足未知时间。
- 对侧实际行为应记录；策略与意图只作为有依据的假设，并列出其他可能解释。
- 后续信息只能触发之后的计划更新，不能倒灌到此前判断。发生早但获知晚的记录也适用此规则。

## E. 消耗后转移

当前通道完成一次交换后，可以检查其他通道的机会，但须同时检查：下一通道的推进条件、同侧参与能力、转移路径、实际守方，以及状态与能力差能否在下一处发挥作用。

这只是条件性模式。当前推进单位消失可能改变继续停留的价值，但不自动证明转移有利；下一处机会、资源安全性与可达性都可能未知。历史案例只提供比较视角，不预设最优答案。

## F. 计划更新

以下新信息可能触发重算：人员到场或退出、推进单位消失、关键能力变化、资源被获取、路径风险变化、同侧无法继续参与。记录变化何时发生、何时获知，以及它影响哪个行动条件。

更新时重新检查选项与停止条件，不因后续结果好坏反推原决策对错。新的假设仍需验证，不能自动写成规则。
