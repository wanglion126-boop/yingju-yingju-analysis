# 分析规范

版本：`1.0.0`。

固定分析链：**当时可知状态 → 双方行为 → 条件变化 → 实际行动 → 可选衔接 → 后续反馈**。

1. 先整理输入事实、推测、未知和矛盾，再评价。输入事实表示材料明确陈述，不等于已经外部核实。
2. 在每个判断节点设定信息截止时间；只有当时已可知的证据能支持当时建议。发生时间未知或只有最后观察时，不补造当前位置与行动先后。
3. 双方行为分别记录，关注行为改变了什么条件。意图解释标记为推测，附证据和可替代解释；未知意图不能替代实际行为。
4. 只比较用户本次问题涉及的行动。每个选项写明成立条件、成本、收益方向、停止条件、简明理由和证据事件；未提供数值不得制造精确收益、概率或胜率。
5. 信息不足时给出条件分支。例如在下一处机会、路径和同侧参与得到确认后才比较相应衔接；不得将“可能”提升为“确定”。未确认“安全资源”存在时，它只是候选类别。
6. 明确区分输入事实、分析解释与建议。行动是否合理取决于当时信息和条件；结果好坏本身不是判定决策对错的依据。
7. 后续反馈单独标明获知时间，用于指出何时需要更新计划，不能用于修饰此前可知状态。不同方案的比较应使用同一信息截止时间。
8. 每轮行动分析默认只提炼**一个关键转折点和一条条件性修正规则**。不能确定时用 `null` 并说明原因，不为了凑结论而补事实。信息整理阶段两者必须为 `null`。
9. 给出可检查的依据、条件和简明理由，无需冗长内部推演。历史案例只作条件性参考；与本任务不匹配的条件需指出。
10. AI 输出默认 `pending_review`。输入问题列出后等待确认；可整理无争议部分，不自动改输入，不继续依赖争议事实的判断，不自动沉淀结论。

复核时区分：输入纠正、对象或时间误读、解释分歧、建议调整、新证据。新证据只有获知时间明确时才能参与相应历史节点判断；事后提供的补充不自动代表当时可知。
