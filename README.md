# yingju-analysis

独立的中性场景时序分析工作区，用于用户提供的离线抽象对抗场景。材料已经使用中性代号；这里不进行原始名称转换、身份还原或来源猜测，不连接客户端和外部服务。

工作流：中性事件输入 → 整理事实与未知 → 梳理双方行为 → 分析条件变化 → 比较后续选择 → 输出可检查的结构化结果。

| 位置 | 用途 |
| --- | --- |
| `AGENTS.md` | 工作入口、访问边界与读取顺序 |
| `context/` | 场景规则、分析规范、输出约定；初始版本均为 `1.0.0` |
| `tasks/<编号>/` | 请求、对象、事件与 manifest；分析时只读 |
| `schemas/` | Draft 2020-12 结构约束 |
| `cases/` | 条件性参考与验证状态；演示不代表已验证 |
| `results/<编号>/` | 信息整理、行动分析及案例草稿 |
| `reviews/` | 用户复核模板与经授权保存的反馈 |
| `prompts/` | 可直接复制的四份短提示词 |

## 新建任务

1. 在 `tasks/` 下新建未使用的编号目录，如 `T002/`，创建 `request.md`、`entities.json`、`events.json`、`manifest.json`。可复制 T001 的结构，但必须替换演示内容并标明实际材料性质。
2. 按 Schema 填写对象与事件；时间统一为从任务约定起点计算的秒数，未知就保留未知。发生时间与获知时间分开记录。
3. manifest 的 `taskId` 与目录一致，引用使用任务目录内的相对文件名；`contextVersion` 记录使用的规则版本，案例只列相关编号。未检查的输入使用 `pending_check`。
4. 让 AI 检查事实、时间与缺失信息；存在问题先确认输入。所有任务均独立成立，不依赖其他项目源码、身份词典、业务映射表或运行环境。

## 首次使用

复制以下指令即可对虚构演示 T001 做信息整理：

> 请按AGENTS.md处理T001。
> 先检查事实、时间和未知项。
> 本轮只完成信息整理，不评价行动对错。
> 结果写入results/T001/，不要修改输入和规则。

继续比较行动时，复制 `prompts/02-比较行动.md`；明确指定节点、比较选项与已确认的输入修订。提示词中的 `T001`、任务路径和结果路径可统一替换为新编号。信息整理与行动分析分轮进行，前一阶段不暗含行动评价。

## 结果、反馈与沉淀

首次结果为 `results/T001/analysis.json` 和 `summary.md`，默认状态 `pending_review`。复核或进入下一阶段时保留原结果，生成如 `analysis-r02.json`、`summary-r02.md` 的配对文件，并记录修订依据。

用户可复制 `reviews/TEMPLATE.md` 填写反馈；保存新反馈文件须有用户授权。只有输入与适用条件明确、用户接受相关结论并明确允许沉淀的结果，才可生成案例草稿。正式案例还须用户确认草稿、目标编号和验证状态；推测不能因入库变为事实。未经真实记录验证的演示始终保留演示标签。

默认不得自动修改 `tasks/` 输入、`context/` 规则、`cases/` 正式案例、Schema 和工作入口。需要改动时先给出明确草稿或差异，按用户授权处理。AI 结论不会自动成为规则。

## 使用边界

仅使用 Markdown、JSON 和 JSON Schema，不需要前端工程、依赖安装或外部服务，也不需要保存任何 API 密钥。目录约束是操作规则，不等于操作系统权限隔离；使用者仍需配合工具权限和路径检查。

T001 与 C001 均为**虚构演示**，未经真实记录验证，也未经用户验证。初始化不执行 T001 分析。Schema 只检查结构，对象引用、时间一致性和推理合理性还需单独检查，不能据此证明结论正确。
